# Proposal Insert

A short paragraph to paste into Upwork proposals. It references the demo honestly,
ties it to the buyer's problem, and points at the part that de-risks the work for them.
Swap the bracketed bits to match each post.

---

## Primary version (general)

> I recently built a production-style demo of exactly this kind of workflow — a pipeline
> that ingests messy documents, extracts the structured fields (IDs, line items,
> quantities, units, dates, notes), and then runs a deterministic validation pass that
> checks every field against a reference list and a set of rules. Clean records pass
> through automatically; anything questionable — a wrong unit, an impossible quantity,
> an unknown code — gets flagged for a quick human review instead of landing wrong in
> the spreadsheet. It's a self-built demo (no client data attached), built with
> FastAPI + Pydantic and a real test suite, and it's designed so the AI extraction step
> plugs into your real documents. I'd adapt the same ingest → extract → validate → route
> approach to your [material schedules / invoices / forms / reports]. Happy to show it
> running on a short call.

---

### Why this phrasing is safe

- "**self-built demo (no client data attached)**" — states the truth up front; no
  implied past engagement.
- "**designed to / I'd adapt**" — future-tense intent, not a claimed result.
- No percentages, dollar figures, or accuracy numbers.
- Leads with the **validation layer**, which is the real, implemented value and the part
  that reduces the buyer's risk.
